# 표를 그릴 때 — html`` 를 쓴다

## 한 줄 요약

`innerHTML` 에 넣을 마크업은 **`html\`\`` 태그드 템플릿**으로 만든다.
그러면 `${}` 안의 값이 자동으로 이스케이프된다.

```js
// 이렇게
tbody.innerHTML = html`${rows.map(r => html`
  <tr>
    <td title="${r.desc}">${r.desc}</td>
    <td>${r.mid_cat || '—'}</td>
  </tr>`)}`;

// 이렇게 말고 (escape 를 빠뜨리면 저장형 XSS)
tbody.innerHTML = rows.map(r => `<tr><td>${r.desc}</td></tr>`).join('');
```

## 왜 이렇게 됐나

2026-08-17, 입출금 표의 거래내용(`desc`)이 escape 없이 렌더되고 있는 것이 발견됐다.
`escapeHtml()` 은 이미 있었고 수표·AR 탭 등 일부는 쓰고 있었지만, **40여 곳에서 빠져 있었다.**

문제의 성격:

- `cf_data` 는 Supabase 에 저장돼 **모든 대시보드 사용자에게 공유**된다.
  한 사람이 넣은 값이 다른 사람 브라우저에서 실행되는 **저장형(stored) XSS** 였다.
- 입력 경로가 셋이다 — 수기 입력 · 엑셀 일괄 업로드 · **클로브 자동적재(은행 적요)**.
  마지막 건 우리가 값을 통제하지 못한다.

근본 원인은 개별 누락이 아니라 **"사람이 매번 기억해야 하는 방어"** 라는 구조였다.
그래서 기본값을 뒤집었다. `html\`\`` 로 만들면 아무것도 안 해도 안전하고,
위험한 쪽(raw)을 쓰려면 명시해야 한다.

## 규칙

| 상황 | 결과 |
|---|---|
| `${값}` | 자동 이스케이프 |
| `${html\`...\`}` (중첩) | 그대로 통과 — 조각 조립 가능 |
| `${배열}` | 자동으로 이어붙음 — **`.join('')` 불필요** |
| `${null}` `${undefined}` `${false}` | 빈 문자열 — `${cond && html\`...\`}` 조건부 렌더 가능 |
| `${0}` | `0` 출력 (falsy 지만 숫자는 나온다) |
| `${raw(값)}` | 이스케이프 안 함 — **정말 필요할 때만** |

⚠ `html\`\`` 안에서 `escapeHtml()` 을 또 부르면 **이중 이스케이프**가 된다
(`A&B` 가 `A&amp;B` 로 화면에 보임). 하나만 쓴다.

⚠ 신뢰할 수 없는 값을 `raw()` 에 넣으면 이 구조가 전부 무의미해진다.

정의 위치: `index.html` 의 `escapeHtml()` 바로 아래.
참고 구현: `renderCFTable()` — 사고가 났던 그 함수이자 첫 전환 사례.

## 검사

```bash
node scripts/check-html-escaping.mjs
```

마크업 템플릿 안에서 **가공 없이 그대로 꽂힌 데이터 필드**를 찾아 실패시킨다(exit 1).
`--audit` 을 붙이면 `raw()` 사용처도 같이 나온다. 특정 파일만 검사하려면 경로를 인자로 준다.

검사기는 오탐을 줄이려고 일부러 좁게 잡는다 — 함수를 거친 값(`${fmt(x)}`)이나
삼항의 조건부에만 등장하는 값은 통과시킨다. **오탐이 많은 검사는 무시당하고,
그러면 진짜 위반이 그 속에 묻히기 때문이다.** 대신 새 데이터 필드가 생기면
`DATA_FIELDS` 에 추가해야 잡힌다.

## 전환 현황

전체 마크업 템플릿 390개 중 `html\`\`` 적용은 아직 일부다(진행률은 검사기가 출력).
나머지는 `escapeHtml()` 을 개별 호출하는 방식으로 **현재 누락 0건**인 상태다.
표를 새로 만들거나 기존 표를 손볼 때 그 함수부터 `html\`\`` 로 옮기면 된다.
한 번에 전부 바꾸지 않은 이유는 매일 쓰는 도구라 대규모 일괄 수정의 회귀 위험이 크기 때문이다.

## 이메일(Edge Function)

주간 리포트 메일 HTML 은 `supabase/functions/send-weekly-report/index.ts` 가 따로 만든다
(화면의 dry-run 미리보기와 **두 벌**이다 — 자세한 건 메일 관련 메모 참고).
거기엔 자체 `escapeHtml()` 이 있고 현재 누락 0건이며, 검사기 대상에 포함돼 있다.
메일 클라이언트는 대개 `<script>` 를 걷어내므로 스크립트 실행보다는 **마크업 주입**
(피싱 `<a href>` 삽입, 표 깨뜨려 금액 은폐)이 실제 위험이다.
