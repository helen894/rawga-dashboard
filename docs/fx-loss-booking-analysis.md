# 7월 외화 미기표 외환차손 — 기표 검토 (결론: cf_data 에 기표하지 않는다)

2026-08-23. 대표님이 "8,538만원 외환차손 기표" 를 승인했으나, 실행 전 검산에서 **금액과 효과가
둘 다 달라** 멈추고 보고했다. 이 문서는 그 근거다.

## ① 금액이 틀렸다 — 8,538만원이 아니라 1억 2,158만원

내가 앞서 낸 85,380,527 은 **잔여 USD 24,932 를 임의 환율 1,480 으로 평가해 상계한 값**이다.
근거 없는 환율이었다. 이동평균 원가법으로 실현분만 계산하면:

| 날짜 | USD | 장부원가 방출 | 실수령 | 실현손실 | 기기표 | 미기표 |
|---|---|---|---|---|---|---|
| 07-09 | 1,000,000 | 1,539,700,000 | 1,491,890,000 | 47,810,000 | 18,010,000 | **29,800,000** |
| 07-13 | 2,840,018 | 4,371,967,807 | 4,280,191,128 | 91,776,679 | 0 | **91,776,679** |
| | | | | | **합계** | **121,576,679** |

잔여 재고 USD 24,932 · 장부 38,380,708 (원가환율 1,539.42) — 미실현이라 기표 대상 아님.
7/6 입금 장부환율 = 5,912,371,015 / 3,839,950 = **1,539.7000**

## ② 기표하면 대조가 나빠진다 — 측정치

| 시나리오 | FX_ADJ | 평균오차 | 최대오차 | 끝점 |
|---|---|---|---|---|
| 현행(기표 안 함) | −125,836,060 | **1,262,728** | **48,335,854** | 708,575,602 |
| 121,576,679 기표 | −4,259,381 | 2,664,973 | 95,587,892 | 708,575,602 |
| 기존 스프레드 제거 | −143,846,060 | 1,269,332 | 48,335,854 | 708,575,602 |

**끝점(오늘 잔액)은 세 경우 모두 같다.** 이게 핵심이다.

## ③ 왜 그런가 — 기표와 플러그는 현금중립 대체재다

`FX_ADJ = fxKrw − (pre_krw + Σ fx_usd 행)` 이므로, fx_usd 태깅 출금을 넣으면 Σ가 줄어
FX_ADJ 가 **정확히 같은 만큼** 올라간다. 잔액은 한 푼도 안 바뀐다. 바뀌는 것은
**그 금액이 과거 날짜에 어떻게 퍼지는가** 뿐이다.

- 현행: 플러그를 환전 비중 램프로 7/9~7/13 에 분산 → 실제 궤적에 더 가깝다
- 기표: 7/9·7/13 두 날에 이산적으로 못 박음 → 7/7~7/8 의 보유기간 재평가 갭이 무보정으로 남음

실제 괴리는 **7/6~7/9 USD 3,839,950 을 들고 있던 3일간의 일별 재평가**에서 나온다.
실현일 두 날에 몰아 넣는 방식으로는 그 모양을 만들 수 없다.

## ④ 앞서 의심한 '기존 스프레드 이중계상' 은 사실이 아니었다

7/9 에 환전 두 다리(−745,945,000 / +745,945,000)가 이미 **실현환율로 상쇄**돼 있고 그 위에
외환차손 −9,005,000 ×2 가 얹혀 있어 이중계상을 의심했다. 제거해서 측정하니 평균오차가
1,262,728 → 1,269,332 로 **7천원 수준만 움직였다**. 현금중립이라 대조로는 구분되지 않는다.
이중계상이 아니다 — 의심을 철회한다.

## ⑤ 그래서 어디에 기표해야 하는가

**cf_data 는 현금 원장이다.** 환전의 두 다리가 이미 실현환율로 들어와 있어 현금은 정확하다.
외환차손은 현금이 나간 사건이 아니라 **손익 분류**다. 여기에 지출 행으로 넣으면 나가지 않은
돈 1.22억을 뺀다.

기표할 곳은 **발생기준 회계장부 / 팀별 손익 대시보드**다(현금 대시보드와 분리된 그 대시보드).
위 ① 표의 날짜·금액을 그대로 쓰면 된다.

## ⑥ 현금 대시보드 표시 — 완료 (2026-08-23)

잔액 대조 카드의 '🔄 외화 환산손익' 줄 아래에 근거 한 줄을 붙였다:

> ↳ 이 중 **121,576,679** 은 **실현됐으나 손익 미기표** — 발생기준 장부 기표 대상

**표시 전용이다 — 현금 계산에는 쓰지 않는다.** 그래서 잔액·대조·차트는 전혀 안 바뀐다.

⚠ **하드코딩하지 않았다.** `cat_data.fx_adjust_base.unbooked_loss` 에서 읽는다. 값이 없거나
0 이면 줄이 사라진다(테스트 `scripts/test-unbooked-fx-loss.mjs` 7/7). Edge `setMeta` 화이트리스트에
그 경로를 추가했으므로 갱신은 이렇게 한다:

```
{ secret, setMeta: { "fx_adjust_base.unbooked_loss": <금액> }, dry: true }
```

**새 외화 거래가 생기면 이 값을 다시 산출해 갱신해야 한다.** 그대로 두면 낡은 금액이 계속
표시된다 — `scripts/verify-fx-loss-booking.mjs` 가 산출식을 갖고 있다.
