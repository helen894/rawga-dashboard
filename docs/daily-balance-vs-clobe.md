# 대시보드 일별 잔액 vs 클로브 실제 잔액 대조 (2026-01-01 ~ 08-23)

`scripts/verify-daily-balance-vs-clobe.mjs` · 클로브쪽 데이터 `docs/audit/clobe-daily-trend-2026.tsv`
(= `get_account_balance_trend(inquiryWeeks=34).checkingTrends` 236일)

⚠ 필드명이 `checkingTrends` 지만 **외화 KRW 환산까지 포함한 총현금**이다 — 8/21 값
708,575,602 이 `bank_snapshot.totalCash`(예금 642,939,378 + 외화 65,636,224)와 정확히 같다.

## 비교 방식 — 레벨이 아니라 일별 증감

`FX_ADJ` 가 **날짜 없는 상수**로 전 구간에 얹히므로(index.html 5155 의 의도된 절충) 레벨
차이는 언제나 약 −1.26억이 깔린다. 증감으로 보면 그 상수가 상쇄돼 **특정 날짜에만 튀는
차이 = 그 날의 실제 데이터 문제**가 드러난다.

## 결과 — 1~6월 데이터 문제 없음

허용오차 100만원(외화 일변동) 기준, 전일 대비 차이가 그 이상 움직인 날은 **5일뿐이고 전부
7/7~7/13** 이다:

| 날짜 | 움직임 |
|---|---|
| 07-07 | +30,539,970 |
| 07-08 | +20,102,258 |
| 07-09 | +64,559,177 |
| 07-10 | +16,335,167 |
| 07-13 | −8,310,875 |

이 구간은 USD 3.84M 통과(7/6 MEDHERBS 59.1억 입금 → 7/9 환전 −7.46억×2 → 7/13 매입대금
−42.8억)로 **상수 FX_ADJ 가 실제 외화 흐름에 수렴하는 구간**이다. 오류가 아니다.

**2026-01-01 ~ 06-30 사이에는 100만원 넘게 튀는 날이 하루도 없다.**
허용오차를 20만원까지 좁히면 그 구간에도 20~90만원 수준이 뜨는데, 전부 외화 재평가다.
근거: 2026-05-03(일요일)은 cf 순flow 0인데 클로브 잔액만 −259,504 움직였다 —
거래가 아니라 보유 외화의 환율 재평가다. 대시보드는 이걸 일별로 추적하지 않는다.

## 다만 실제 영향이 하나 있다 — 과거 잔액이 약 1.26억 낮게 보인다

| 날짜 | 레벨 차이(대시보드 − 클로브) |
|---|---|
| 2025-12-31 | −126,381,580 |
| 2026-06-30 | −127,545,608 |
| 2026-07-31 | −2,266,405 |
| 2026-08-21 | **0** |

`FX_ADJ = −125,836,060` 을 전 구간에 얹기 때문에 **1~6월 일별 잔액 추이가 통째로 약 1.26억
낮게 그려진다.** 오늘 시점은 0으로 맞으므로 KPI·대조 카드는 정상이고, **어긋나는 건 과거
구간의 선 높이뿐**이다.

이건 index.html 5155 주석이 스스로 밝힌 절충이다:
> ⚠ 절충: 과거 시점 잔액도 '오늘 기준' 누적 환산손익을 안고 있게 된다. 기간별로 배분하는
> 게 정확하지만 그럴 근거 데이터가 없다. 대신 차트·KPI·리포트가 서로 어긋나지 않는다.

### 조치 완료 — fxAdjAt(date) 도입 (2026-08-23)

`FX_ADJ` 를 상수에서 **날짜별 배분**으로 바꿨다. `index.html` 의 `buildFxRamp_` / `fxAdjAt` /
`fxAdjTail`, 테스트는 `scripts/test-fx-adj-at.mjs` (19/19).

**배분 규칙 2가지**
1. `fx_adjust_base.through`(=2026-06-30) 까지는 **0**. 그 구간은 `pre_krw` 가 장부를 평가액에
   맞춰 둔 구간이다(그 note 의 "대조 검증 오차 −69,216원").
2. through 이후는 **환전 시점에 실현된다.** USD 입금이나 USD 직접지급은 장부와 평가를
   어긋내지 않는다 — 환율이 다른 환전이 어긋낸다. 그래서 through 이후 `fx_usd` 행 중
   환전 성격(`계좌간이체`·`외환차손`)만 |금액| 비중으로 램프를 만든다.

**실측 개선** (`scripts/verify-daily-balance-vs-clobe.mjs`, `--const` 로 종전 방식 비교)

| 모델 | \|차이\| 평균 | 최대 |
|---|---|---|
| 상수(종전) | 101,758,097 | 128,522,707 (07-02) |
| 전체 |금액| 램프 | 2,054,931 | 65,715,449 (07-06) |
| **환전건 램프(채택)** | **1,262,728** | 48,335,854 (07-08) |

연초 레벨 차이 **−126,381,580 → −545,520**. 오늘은 종전과 같이 0 이므로 현금 KPI·잔액 대조
카드는 변화 없다. 최대오차 4,834만원은 7/7~7/8 이틀치인데, 실제 환전이 cf_data 기재일(7/9)보다
앞서 시작된 탓이다.

**부수 효과 — '현금 마이너스' 표시가 사라졌다**
총자산 구성 차트에서 연초~5/20 사이 **40일이 마이너스로 계산되고 있었다**(3/10 −0.89억 등).
실제 바닥이 아니라 이 버그의 산물이었고, 도입 후 **음수일 0일**이 됐다
(3/10 +0.36억 · 3/17 +0.70억 · 5/15 +0.78억 · 5/20 +0.59억).
2026-08-22 에 차트에서 지운 '현금 마이너스' 안내가 가리켰던 현상 자체가 버그였다.

**적용 지점** — 과거 날짜를 그리거나 집계하는 곳만 바꿨다. 오늘 기준으로 누적하는 곳
(`renderBankRecon` 의 `calc`, KPI 의 `cash`, 궤적 시작점)은 `fxAdjAt(오늘) === FX_ADJ` 라
손대지 않았다.

| 함수 | 무엇 |
|---|---|
| `renderCashChart` | 일별 잔액 추이 (기준일−90일 ~ 기준일) |
| `renderAssetMixChart` | 총자산 구성 (연초 ~ 오늘) — 영향이 가장 컸다 |
| `calcKPIs` | **현금 잔액 KPI 카드** — `cash` 는 `ref`(보고기준일)까지 누적한다 |
| `renderRegularReport` | 정기보고 현금·런웨이 — 같은 이유 |
| 월간 KPI/생키 | `pmEndCash`·`mEndCash` |
| 주간 리포트 | `pwEndCash`·`wkEndCash` |
| `computeWeeklyCashSeries` | `fxAdjBefore` 인자 추가 — 주차 시작 시점과 오늘의 조정이 갈린다 |

### ⚠ 첫 구현에서 놓쳐서 화면이 어긋났던 것
`calcKPIs` 와 `renderRegularReport` 의 `cash` 를 "오늘 기준"으로 착각해 손대지 않았다.
실제로는 **`refDate` 까지 누적**한다. 그래서 보고기준일을 과거로 옮기면 **추이 차트는 고친 값,
KPI 카드는 옛 값**이 나와 1.26억 갈렸다 — 대표님이 바로 발견했다.
교훈: `INIT_CASH + FX_ADJ` 를 쓰는 지점은 누적 상한이 `today` 인지 `ref` 인지 **반드시 확인**할 것.
`ref` 면 `fxAdjTail(ref)` 보정이 필요하다.

검증: 보고기준일 1~8월 8개 지점에서 KPI 경로와 차트 경로가 **전부 0원 차이**로 일치한다.

**⚠ 안전장치** — `through` 가 없거나 through 이후 환전 행이 없으면 램프를 만들지 않고
**종전처럼 상수로** 동작한다. 분류 체계가 바뀌어 환전 행을 못 찾을 때 과거 잔액을 조용히
왜곡하지 않기 위한 것이다. 환전을 다른 중분류로 분류하게 되면 `FX_CONV_MIDS` 에 넣어야 한다.
