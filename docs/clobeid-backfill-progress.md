# 2026-03~06 clobe_id·tx_at 백필 진행 표식

**목표**: 2026-03-01 ~ 06-30 실거래 1,044건에 `clobe_id`·`tx_at` 을 붙인다.
**방식**: 재적재 금지. `cf-clobeid-backfill.mjs` 로 기존 행에 두 필드만 patch(멱등).

## 왜 재적재가 아닌가

3~6월은 `clobe_id` 가 전무해서 push 의 중복 판정이 (거래일+거래내용+금액+상태) 로 떨어진다.
기존 적요는 은행 원본 문자열(`스마트스토어정`·`신동섭`·`(유)바다향`)이고 적재는 거래처명을
넣는다(`네이버파이낸셜 주식회사`·`은혜수산`·`바다향`). 같은 거래인데 문자열이 달라 안 걸린다.
**실측: 재적재하면 667건(63.9%)·408.5억이 이중계상된다.** 2026-01-28 에 실제로 1건 났다.

### 외화계좌 행은 백필 대상이 아니다
`cf_data` 는 원화 환산액으로 들어 있고 클로브는 USD 원금이라 금액으로 맞출 수 없다.
3/13·3/16·3/17 에서 6건 나왔고 앞으로도 계속 나온다 — 오탐이 아니다.

금액이 같아 잔액·집계는 안 틀린다. 거래시각만 미지정으로 남는다.

## 이어받는 방법

```bash
# 1) 클로브에서 구간 조회 (Claude 세션에서만 가능)
#    get_labeled_transactions  startDate/endDate/size=100, hasNext 면 cursor 로 끝까지
# 2) TSV 로 저장 — id \t 계좌 \t YYYY-MM-DDTHH:MM:SS \t 입금 \t 출금 \t 적요 \t 거래처명
# 3) dry-run → 확인 → --apply
node scripts/cf-clobeid-backfill.mjs --clobe <파일.tsv> --from YYYY-MM-DD --to YYYY-MM-DD
node scripts/cf-clobeid-backfill.mjs --clobe <파일.tsv> --from YYYY-MM-DD --to YYYY-MM-DD --apply
```

한 번에 5~7일씩 처리한다(클로브 한 페이지 100건 이내). 이미 붙은 행은 `대상 0건` 으로 지나간다.

## ⚠ 끝나고 반드시 할 것

**백필은 금액 합계 검증에 걸리지 않는다.** `clobe_id` 를 붙일 뿐 금액을 안 바꾸므로,
잘못된 id 를 붙여도 잔액·집계는 그대로 맞는다 — **틀려도 조용하다.**
그래서 전 구간을 `cf-ingest-verify.mjs` 로 대조해 `clobe_id` 가 실제로 그 거래를
가리키는지 확인해야 한다. 이것이 이 작업의 유일한 방어선이다.

- 3~6월 외화 행은 `fx_usd` 태깅이 없다(백필 대상에서 제외). `pre_krw` 상수에 뭉쳐 있어
  FX_ADJ 문제의 근원으로 남는다 — 별개 과제.
- `INIT_CASH` 조정과 `pre_krw` 보정은 1~2월 백필 건으로 이미 대기 중
  (docs/janfeb-backfill-2026.md 참고).
