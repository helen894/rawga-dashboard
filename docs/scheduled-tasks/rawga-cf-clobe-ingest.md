RAWGA 자금 대시보드의 입출금 내역(cf_data)에 클로브 은행 거래를 자동 적재한다. 세션 요약은 조용히 — 이상이 있을 때만 자세히 남긴다. 다만 **슬랙 DM은 매 실행마다 반드시 보낸다**(5단계).

## 원칙 (반드시 지킬 것)
- **오늘자도 적재한다** — 3단계 명령에 `--allow-today` 를 붙인다(안 붙이면 스크립트가 오늘자를 자동으로 뺀다).
  - 오늘 스냅샷은 미완성이다. 오후 거래는 다음 실행 때 **새 transactionId 로 추가**되므로 반복 실행하면 저절로 채워진다.
  - 오전에는 클로브가 거래처를 아직 못 붙인 건이 있어 적요가 은행 원본 문자열로 들어간다. 나중 실행에서 Edge 가 **자동으로 새 적요로 갱신**한다(사람이 대시보드에서 고친 적요는 보호). 그래서 당일 적재가 안전해졌다.
- **반드시 하루 단위로** 조회·저장·적재한다. 여러 날을 한 파일에 담으면 **외화 환율 역산이 깨져** 검증이 실패한다(환율이 날마다 다름 — 2026-07 실측 1,489~1,555원/USD).
- 판단이 필요한 검증은 프롬프트가 아니라 **스크립트가** 한다. 스크립트가 중단하면 그대로 따르고 억지로 우회하지 말 것.
- 시크릿 값을 출력하거나 요약에 쓰지 말 것.

## 대상 기간 — 매 실행마다 오늘 포함 최근 6일을 하루씩
평일(월~금)에만 실행되므로 **오늘부터 5일 전까지 6일**을 각각 처리한다.
- 토요일 실행이 없으므로 **월요일 실행이 금요일 거래를 담당한다.** 오늘 하루만 보면 금요일 데이터가 영영 안 들어간다.
- 오늘을 앞에 더한 것이지 과거 구간을 줄인 게 아니다. 5일 전까지 훑는 건 연휴 대비 여유분이므로 그대로 둔다.
- 이미 적재된 날은 `추가 0`으로 지나간다(clobe_id 중복 차단). 반복해도 안전하다.
- 5일을 넘는 연휴 뒤에는 누락될 수 있다. 요약에 **처리한 날짜를 모두** 남겨 사람이 공백을 알아볼 수 있게 한다.

## 1) 클로브에서 거래내역 조회
클로브 MCP 커넥터 사용:
1. `get_my_context` → **(주)로가** companyId (businessRegNo 1768101964, 보통 `31CbqJ82UGIZTXzfKRPd2`). (주)로가JHT·로가온은 대상 아님.
2. `get_scraping_status` 로 BANK 자산의 `scrapedAt` 확인. **어제보다 이전이면 수집이 멈춘 것이므로 적재하지 말고 그 사실을 요약에 남기고 종료**한다(재수집은 사용자가 app.clobe.ai에서 직접 해야 하며 MCP로는 트리거할 수 없다).
3. 대상 날짜마다 `get_labeled_transactions` 로 **하루씩** 조회: `startDate`=`endDate`=대상일, `size`=100
4. 응답의 `hasNext` 가 true 면 `nextCursor` 를 `cursor` 로 넘겨 **끝까지** 모두 받는다. 한 페이지라도 빠지면 스크립트가 합계 불일치로 중단시킨다.
   - 여러 페이지를 합칠 때는 **하나의 객체로** 만든다: `content` 는 이어붙이고, `totalElements`·`inAmountSumKrw`·`outAmountSumKrw` 는 (페이지마다 같은 값이므로) 그대로 하나만 쓴다. 페이지 객체를 배열로 담으면 합계가 중복 합산돼 검증이 깨진다.
5. `get_bank_accounts` 를 한 번 호출해 **기준환율**과 **외화계좌 목록**을 함께 구한다. 둘 다 3단계 적재 때 넘긴다.
   - 기준환율(`--fx-ref`): `accountType`=`FX` 인 계좌의 `krwBalance / balance` (= 클로브 평가환율, 통화가 같으면 계좌 불문 같은 값)
   - 외화계좌 목록(`--fx-accounts`): `accountType`=`FX` 인 계좌 전부를 `bankAccountId:currencyCode` 로 이어붙인다. 현재는 `56034:USD,145016:USD`
   - 둘 다 없으면 스크립트가 직전 캐시로 버티고, 캐시도 없으면 검증이 약해진 채(환율 밴드 100~5000, 계좌명 정규식 판정) 진행하며 경고를 찍는다. 조회 실패 시 그대로 진행하되 요약에 남긴다.

커넥터 조회가 안 되면 아무것도 하지 말고 사유만 남기고 종료.

## 2) 응답을 파일로 저장 (원본 그대로) — 날짜별로 각각
받은 응답을 **손으로 요약·재구성하지 말고 그대로** 저장한다. 거래가 0건인 날은 건너뛴다.
- 경로: `C:/Users/RAWGA/AppData/Local/Temp/clobe-cf-YYYYMMDD.json` (YYYYMMDD=대상일)

## 3) 검증 → 적재 (날짜별로 각각)
```bash
cd "C:/Users/RAWGA/Downloads/rawga-dashboard-git"
node scripts/clobe-cf-ingest.mjs "C:/Users/RAWGA/AppData/Local/Temp/clobe-cf-YYYYMMDD.json" --dry-run --allow-today --fx-ref <환율> --fx-accounts <id:통화,...>
```
먼저 `--dry-run` 으로 검증표를 확인한다. 스크립트가 하는 일:
- transactionId 중복 제거(라벨 다중이면 같은 거래가 여러 행으로 옴)
- dedupe 건수 vs `totalElements` 대조
- API 합계 vs 계산 합계 대조 → **한 방향만 부풀면 행 누락으로 보고 중단**
- **외화(FX)는 그날 잔차에서 환율을 역산해 원화로 환산한 뒤 함께 적재**한다(더 이상 제외하지 않음)
  - 역산값이 `--fx-ref` 기준 ±5% 밴드를 벗어나면 행 누락으로 보고 중단한다. 환율이 실제로 그만큼 움직인 거라면 최신 기준환율을 다시 넘기면 통과한다 — 임의로 우회하지 말 것.
  - 외화 순액이 0인 날(환전·pass-through)은 역산이 불가능해 **기준환율로 환산**한다. 순액은 환율과 무관하게 0이고 총입금·총출금 크기만 영향을 받는다. `--fx-ref` 가 없으면 이 날의 외화 행은 제외되므로 기준환율을 꼭 넘길 것.
- 외화계좌는 `--fx-accounts` 화이트리스트로 판정한다. 목록에 없는데 계좌명이 외화계좌처럼 생긴 거래가 나오면 **새 외화계좌가 열린 것**이므로 중단한다 — `get_bank_accounts` 를 다시 뽑아 목록을 갱신할 것(방치하면 USD 원금이 원화로 섞여 적재된다). 그날 통화가 둘 이상이어도 단일 환율이 성립하지 않아 중단한다.
- **적요 갱신**: 이미 적재된 행이라도 클로브가 거래처를 뒤늦게 매핑했으면 Edge 가 새 적요로 갱신하고 학습 매핑 키도 함께 옮긴다. 대시보드에서 사람이 고친 적요는 건드리지 않는다. 갱신이 일어나면 `적요 갱신 N건` 과 건별 `"before" → "after"` 가 출력된다
- 취소·정정 거래(입금·출금 레그가 동액이라 순액 0)는 경고만 남기고 통과
  - 다만 그 규모가 **그날 총액의 50% 초과 + 1천만원 초과**면 계좌 단위 행 누락으로 보고 중단한다. 클로브에서 그날 취소·정정이 실제로 그 규모인지 확인하고, 맞을 때만 `--allow-large-cancel` 을 붙여 재실행한다. 확인 없이 붙이지 말 것.
- `--allow-today` 없으면 오늘자 제외 (지금은 붙이므로 포함)

exit code 2 또는 `합계가 맞지 않습니다` 가 나오면 **그 날짜는 적재하지 말고** 사유를 요약에 남긴다. 나머지 날짜는 계속 진행한다.
문제 없으면 `--dry-run` 없이 다시 실행해 실제 적재한다. 중복은 clobe_id 로 자동 차단되므로 재실행해도 안전하다.

## 4) 요약 남기기
- **정상**: 추가된 게 있으면 날짜별 한 줄(`<날짜> 추가 X · 중복 Y`), 6일 모두 추가 0이면 `최근 6일 신규 없음` 한 줄로 압축. 적요 갱신이 있었으면 건수를 덧붙인다.
- **자세히 남길 것**:
  - 검증 중단(사유·날짜)
  - 수집이 멈춰 있음(`scrapedAt` 명시) — 사용자가 재수집해야 하므로 반드시 눈에 띄게
  - 커넥터 조회 실패
  - 적재 실패(HTTP 오류). 특히 `동시 수정 충돌 — 4회 재시도 실패` 는 대시보드가 계속 쓰고 있다는 뜻이니 그대로 전달
  - **환전 거래**(외화 계좌 ↔ 원화 계좌): 환산에 쓰는 환율은 클로브 평가환율이라 실제 환전 대금과 차이날 수 있다(2026-07-09 실측 1,801만원 차). 건별로 남겨 사람이 확인하게 할 것
  - **과대 취소 레그로 중단**된 날(사유·금액·비율) — `--allow-large-cancel` 을 임의로 붙이지 말고 사람 확인을 요청할 것
  - **새 외화계좌 감지로 중단** — accountId·계좌명을 그대로 남기고 목록 갱신이 필요하다고 알릴 것

## 5) 슬랙으로 결과 발송 — 매 실행, 성공·실패 모두
`slack_send_message` 로 **본인 DM** 한 건 발송: `channel_id` = `U0794BSDK43`.

- 정상: `💸 입출금 적재 <처리한 날짜 범위> · 추가 <합계>건` — 추가가 있은 날은 날짜별로 한 줄씩 덧붙이고, 6일 모두 0건이면 `신규 없음` 한 줄로 끝낸다. 적요 갱신이 있었으면 `· 적요 갱신 N건` 을 같은 줄에 덧붙인다(건별 목록은 슬랙에 넣지 않는다 — 요약에만).
  - 오늘자는 스냅샷이 미완성이라 오후 거래가 빠져 있을 수 있다. 오늘 건수를 확정치로 단정하지 말 것.
- 이상: 맨 앞에 `⚠️` 를 붙이고 **무엇이 실패했는지 + 사람이 할 조치**를 덧붙인다.
  (검증 중단 날짜·사유 / 수집 멈춤 → `app.clobe.ai 에서 직접 재수집 필요` / 동시 수정 충돌 / 환전 거래 건별 확인 요청)
- **시크릿·계좌번호는 넣지 말 것.**
- 발송이 실패해도 이미 적재된 거래는 유효하다. 재시도는 1회만 하고 안 되면 세션 요약에만 남긴다.
- 조회 자체가 안 돼 적재까지 못 갔더라도 **슬랙은 보낸다** — 조용하면 정상인지 태스크가 죽은 건지 구분이 안 되기 때문.
